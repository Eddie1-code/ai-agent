# 生活导师知识库-百炼上传与验证指南（Meta切分版）

## 一、目标
- 将 12 份“切片版”文档上传到百炼知识库，并开启 `metadata` 抽取。
- 让每个 chunk 都带上可过滤的元信息（如领域、主题、风险等级、来源文档）。
- 支持后续在代码侧做“按 metadata 过滤检索”或“返回命中文档来源”。

## 二、上传前文档规范（先统一再上传）
你当前的 `-切片版.md` 结构已经很好（`[ID] + 适用范围 + 结论 + 步骤 + 风险 + 复盘`），建议仅增加一行“可抽取元信息头”：

```md
## [LIFE-FIN-001] 月光如何存钱
META: domain=finance; topic=budget; risk=low; audience=adult; source=个人财务与消费决策
**适用范围**：储蓄困难。
**结论**：先自动储蓄，再优化消费。
...
```

建议字段（最少 6 个）：
- `doc_id`：文档ID，如 `LIFE-FIN`
- `chunk_id`：切片ID，如 `LIFE-FIN-001`
- `domain`：领域，如 `finance` / `emotion` / `career`
- `topic`：主题标签，如 `budget` / `delay` / `conflict`
- `risk`：`low` / `medium` / `high` / `crisis`
- `source`：来源文档中文名

说明：
- `chunk_id` 可以从二级标题 `## [LIFE-XXX-001]` 自动提取。
- `source` 可以用文件名提取。
- `risk` 建议通过规则或大模型抽取（如包含“自伤/伤害他人”可判 `crisis`）。

## 三、百炼侧配置（对应你截图的流程）
### 1）上传入口
- 进入知识库，点击 `导入数据`。
- 文档处理阶段打开 `metadata抽取`。
- 切分方式优先选 `智能切分`（你的文档是短结构块，兼容性最好）。

### 2）Meta信息模板建议
在“新增 Meta 信息模版”中配置以下字段：
- `chunk_id`（变量，参与检索，参与模型回复）
- `domain`（关键词搜索或正则，参与检索）
- `topic`（关键词搜索，参与检索）
- `risk`（大模型或规则，参与检索、参与回复）
- `source`（变量，参与回复）
- `author`（常量，不参与检索，可参与回复）

推荐：
- “参与检索”至少开启：`chunk_id/domain/topic/risk`
- “参与模型回复”至少开启：`source/risk/chunk_id`

### 3）标签策略（文档级）
给每个文档加统一标签，建议：
- 公共标签：`生活导师`、`行动优先`、`安全边界`
- 领域标签：`学习`、`职业`、`关系`、`财务`、`危机` 等

标签用于“文档级筛选”，metadata 用于“chunk级过滤”，二者可叠加。

## 五、验证清单（上传后立即做）
### 1）Meta抽取验证
- 打开任一文档的 `Meta信息`，确认能看到 `chunk_id/domain/topic/risk/source`。
- 抽查每份文档至少 2 个 chunk，确认字段非空。

### 2）检索验证（关键）
- 用问题“我月光怎么存钱”应优先命中 `domain=finance`。
- 用问题“我有自伤冲动怎么办”应命中 `risk=crisis` 且来源危机文档。
- 用问题“我总拖延”应命中 `time/goal` 相关 chunk。

### 3）回答结构验证
- 回答仍需保持：结论、可执行步骤、风险提醒、复盘问题。
- 高风险问题必须出现转介信息（热线/本地紧急支持）。

## 六、代码侧能否获取 metadata？有必要吗？
可以，但分两层看：

1) 检索阶段  
- 你现在用的是云端检索器 `DashScopeDocumentRetriever`。  
- 只要百炼侧成功抽取 metadata，检索系统就可以利用这些字段做召回/过滤（是否开放显式过滤取决于你调用参数能力）。

2) 应用返回阶段  
- 你当前 `MentorApp` 里只取了 `chatResponse.getResult().getOutput().getText()`，没有把检索命中的文档元信息透传给前端。  
- 如果你要在前端显示“命中来源/风险标签/chunk_id”，需要在响应链路里额外读取并返回检索上下文元数据。

是否有必要：  
- **强烈建议做 metadata**，因为它能显著提升检索稳定性与可控性。  
- 但“是否必须在前端显示 metadata”取决于产品目标：  
  - 只追求回答质量：可先不展示；  
  - 需要可解释性、审核追踪、AB测试：建议展示 `source/chunk_id/risk`。
